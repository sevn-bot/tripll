Getting started

Install tripll, run setup and doctor, onboard a repo with init or new, then start a run — with the compounding loop available from day one.

Why before how

tripll is not only a dispatch engine. Each run can leave behind durable rules (with file:line provenance), calibration against the ledger, and scoped context packed into the next brief. Operators activate rules; agents propose but never promote (R27).

New user path

Start here if you have only pip install tripll or uv tool install tripll and want to reach a started run without reading source:

uv tool install tripll        # or: pip install tripll
tripll setup                  # once per machine
tripll doctor                 # confirm backends + layout
cd ~/code/my-project && tripll init     # brownfield
# — or —
tripll new my-project && cd my-project  # greenfield
tripll doctor
tripll rules derive           # optional: cited rules from evaluation
tripll validate-plan docs/plans/*-wave-plan.md
make run-set SET=my-set       # or tripll run runs/input/my-set

Full walkthrough: onboarding runbook · rules runbook (in-repo).

What init writes

  • tripll.toml — repo layout: specs_dir, prds_dir, plans_dir
  • docs/specs/, docs/prds/, starter v3 wave plan
  • docs/evaluation-<date>.md — brownfield assessment with file:line evidence
  • .tripll/rules/ — after tripll rules derive (proposed until promoted)
  • runs/ — input/processing/processed/failed folders

tripll init is idempotent — operator-edited files are not overwritten.

Config precedence

  1. CLI flags (--backend, --model, …)
  2. Environment (TRIPLL_*)
  3. Repo tripll.toml
  4. Machine ~/.config/tripll/config.toml (from tripll setup)

tripll never stores provider credentials in config files (R24).

tripll checkout (contributors)

git clone https://github.com/sevn-bot/tripll
cd tripll
make setup      # uv sync (dev/api/obs) + git hooks
make init       # creates runs/{input,processing,processed,failed}/

First run (operator quick path)

# Drop ONE input set under runs/input/<name>/ then:
make plan-set SET=my-set     # parse + validate the graph (no dispatch)
make run-set  SET=my-set     # start the run → stops at the Pre-0 gate

# Resolve the Pre-0 gate, then continue:
make finish-pre0 RUN=<run-id>

# Inspect progress at any time:
make status RUN=<run-id>

Input shapes

tripll always takes a directory under runs/input/<name>/ and auto-detects the mode:

ModeUse
A — parallel-wave setA coordinated multi-plan manifest (parallel-wave.md + one *-wave-plan.md per row).
B-v1 — execution graphA single wave-plan with a ## tripll execution graph table (recommended).
B-legacy — plain wave filesFiles clustered into lanes by path overlap only.
